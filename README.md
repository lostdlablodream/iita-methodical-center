# Методика

Учебный сервис записи преподавателей ИИТА СПбГУПТД на методические консультации и выявления их потребностей. Тема объединяет каталог консультаций, выбор слота, оформление записи, раздел «Мои записи» и сбор обобщённых методических запросов.

## Статус: scaffold

Создан общий commit-ready каркас без реализации личных страниц:

- четыре HTML-страницы с едиными header/nav/footer, skip link и демонстрационным badge;
- светлый адаптивный `common.css`, общие элементы форм, карточки, уведомления и skeleton-состояния;
- ES-модули конфигурации, форматирования Europe/Moscow, предметных констант и общих компонентов;
- демонстрационный `docs/data/seed.json`: 20 институтов, 6 тем, 12 консультаций и 31 слот;
- проектный архитектурный контракт и дорожная карта.

Пока **не реализованы** repository/storage, загрузка каталога, фильтры, создание и отмена записей, виджет погоды, Python backend, SQLite, Docker и публикация. Отключённые элементы форм намеренно показывают будущую структуру, а не рабочую функциональность.

## Стек и ограничения

- HTML, CSS и vanilla JavaScript ES modules.
- Без npm, React, сборщиков, внешних шрифтов и CDN.
- Все ссылки и ресурсы сайта относительные; ES-модули запускаются через HTTP, а не через `file://`.
- GitHub Pages планируется из `main` / `docs`; `.nojekyll` уже добавлен.
- Backend запланирован на Python stdlib и SQLite в Docker. Его промышленный адрес и любые инфраструктурные секреты в репозиторий не включаются.

## Локальный запуск

Из корня репозитория:

```bash
python3 -m http.server 8000 --directory docs
```

Затем открыть локальный просмотр на `http://localhost:8000`. Остановка сервера — `Ctrl+C`. Проверка синтаксиса демонстрационных данных:

```bash
python3 -m json.tool docs/data/seed.json > /dev/null
```

## Базовый сквозной путь

Это **целевой сценарий следующих спринтов**, а не заявление о готовой функциональности:

1. На главной определить методический запрос и перейти в каталог.
2. Найти консультацию поиском и минимум двумя фильтрами, сравнить формат и слоты.
3. Передать `consultationId` и `slotId` через относительный URL на оформление.
4. Проверить ввод, потребности, доступность места и повторную отправку.
5. Сохранить запись через единый repository и увидеть её в «Моих записях» после обновления.
6. Отменить запись, освободить место и проверить обновлённый статус.
7. Отдельно проверить погоду для очной консультации: загрузка, результат, ошибка и повтор; виджет не должен блокировать запись.

Для серверного режима конфликт на слоте с `capacity = 1`, идемпотентность и владение записью описаны в `ARCHITECTURE.md`.
